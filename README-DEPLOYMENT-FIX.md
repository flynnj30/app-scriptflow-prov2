## Why the reported errors occurred

1. `popup.ts:285` was caused by popup-style authentication/COOP interaction. ScriptFlow uses Firebase redirect authentication instead of `signInWithPopup`.
2. The `message channel closed` error was made worse by an application-level `chrome.runtime.onMessage` listener that returned `true` without completing the extension response. That listener has been removed.
3. Transcript Studio no longer calls a separate `/health` endpoint before every transcription. It posts directly to `/transcribe`, which removes the unnecessary health-request failure path.
4. Transcript Studio no longer depends on Puter WebSockets. It sends the selected file to the same-origin FastAPI service using `faster-whisper`.
5. `ERR_BLOCKED_BY_CLIENT` is generated by browser privacy/ad-blocking software, not by FastAPI. Same-origin `/transcribe` removes the cross-origin dependency used by the old workflow, but a browser extension can still block requests.
